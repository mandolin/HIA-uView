# Manual migration guidance for uView-family applications / uView 系应用的人工迁移指引

HIA-uView deliberately keeps familiar `u-*` template names and `U*` exports for the components it currently implements. This lowers the reading and migration barrier for uView, uView2, uView-Pro, and uview-plus users, but it is **not** a fork with a complete upstream API surface and does not promise compatibility with any upstream release, plugin, theme, or application behavior.

HIA-uView 有意为当前已实现组件保留熟悉的 `u-*` 模板名称和 `U*` 导出。这会降低 uView、uView2、uView-Pro 与 uview-plus 使用者的阅读和迁移门槛，但它**不是**具备完整上游 API 面的 fork，也不承诺兼容任一上游 release、plugin、theme 或应用行为。

## Before changing code / 修改代码前

1. Read the [component index](components.md), each linked component contract, [runtime consumption](runtime-consumption.md), [compatibility profile](compatibility.md), and [upstream source-intake policy](upstream-source-intake.md).
2. Compare only the components your application actually owns. HIA-uView currently has 107 pre-release component contracts. The [API compatibility inventory](api-compatibility.md) covers the 99 names shared with the fixed uView-Pro 0.6.15 comparison and reports 1,740 structural API items: 47 compatible, 340 mapped, and 1,353 unsupported. Matrix v2 binds a complete semantic review to all 127 P0 items: 43 are compatible, 84 require explicit call-site adaptation, none remains unsupported, and all 127 now have repository runtime evidence. The [migration action packet](migration-actions.md) explains all 127 P0 items without editing consumer code. HIA-uView now delivers precise types for the audited form/input, choice/switch, selection/date/numeric/upload, ten overlay/feedback/navigation surfaces, and the 13-component display/media/list/local-action surface linked from the [component index](components.md). Toast component-ref `show/close/hide` and explicitly scoped `useToast`/`useModal` are available, but the services remain mapped because applications must replace upstream global/page event-bus, callback, and navigation behavior with caller-owned scope/host wiring. It still does not promise all-component global declarations, a package-stable/public Easycom contract, request, storage, router, business-module layers, built-in file transport, or complete upstream equivalence. `u-navbar` and `u-notice-bar` remain distinct contracts rather than aliases of `u-nav-bar` and `u-notice`.
3. Keep the application responsible for data, routes, requests, identity, permissions, domain text, business validation, and lifecycle decisions. HIA-uView-Biz helpers, when they exist, belong in the separate HIA-uView-Biz repository.

1. 阅读 [component index](components.md)、每个关联组件契约、[runtime consumption](runtime-consumption.md)、[compatibility profile](compatibility.md) 及 [upstream source-intake policy](upstream-source-intake.md)。
2. 只比较应用实际拥有的组件。HIA-uView 当前有 107 个预发布组件契约。[API 兼容盘点](api-compatibility.md)覆盖与固定 uView-Pro 0.6.15 比较同名的 99 项，并报告 1,740 个结构 API item：47 个 compatible、340 个 mapped、1,353 个 unsupported。matrix v2 为全部 127 个 P0 item 绑定完整 semantic review：43 个 compatible、84 个需要显式调用点适配、0 个仍 unsupported，且全部 127 个现已具备仓内 runtime evidence。[迁移动作包](migration-actions.md)会在不修改 consumer code 的前提下解释全部 127 个 P0 item。HIA-uView 现已为受审 form/input、choice/switch、selection/date/numeric/upload、十个 overlay/feedback/navigation 表面，以及[组件索引](components.md)所链接的 13 组件展示/媒体/列表/局部操作表面提供精确类型。Toast 组件 ref `show/close/hide` 与显式作用域 `useToast`/`useModal` 已可用，但 service 仍为 mapped，因为应用必须把上游 global/page event bus、callback 与导航行为改为 caller-owned scope/host 接线。它仍不承诺全组件 global declaration、包级稳定/公开 Easycom 契约、request、storage、router、业务模块层、内建文件 transport 或完整上游等价。`u-navbar` 与 `u-notice-bar` 仍是独立契约，不是 `u-nav-bar` 与 `u-notice` 的别名。
3. 应用仍负责数据、路由、请求、身份、权限、领域文字、业务校验和生命周期决定。未来 HIA-uView-Biz 的辅助工具也属于独立的 HIA-uView-Biz 仓库。

## Manual migration steps / 人工迁移步骤

| Step / 步骤 | Do / 应做 | Do not infer / 不可推断 |
| --- | --- | --- |
| 1. Choose components / 选择组件 | Replace one documented component at a time using its explicit `U*` import or explicit `UView` plugin registration. / 逐个替换已有契约的组件，使用显式 `U*` import 或显式 `UView` plugin 注册。 | Do not globally replace every `u-*` tag or assume an unlisted component exists. / 不要全局替换所有 `u-*` tag，也不要假定未列组件存在。 |
| 2. Import styles / 导入样式 | Import `style.css` explicitly in application-owned global style setup. / 在应用拥有的全局样式设置中显式导入 `style.css`。 | Do not expect module import or plugin registration to inject theme/style automatically. / 不要期待 module import 或 plugin 注册自动注入 theme/style。 |
| 3. Own state / 保持状态所有权 | Bind props and handle emitted intent in application code. `UForm`/`UFormItem` may run caller-declared rules and restore registered snapshots only through explicit methods; ordinary controlled components still report intent. / 在应用代码中绑定 props 并处理 emit 意图。`UForm`/`UFormItem` 可运行调用方声明的规则，并且只通过显式方法恢复已注册快照；普通受控组件仍只报告意图。 | Do not expect implicit model writes, requests, option fetching, navigation, persistence, backend submission, or inferred domain rules. / 不要期待隐式模型写入、请求、获取 options、导航、持久化、后端提交或推断领域规则。 |
| 4. Verify evidence / 验证证据 | Run repository-local checks appropriate to the documented profile and review declared compatibility evidence. / 运行适用于已记录 profile 的仓内检查，并复核声明的 compatibility evidence。 | Do not call jsdom/compiler output DevTools, device, accessibility, App/H5, cross-platform, or release proof. / 不要把 jsdom/compiler 输出称为 DevTools、真机、无障碍、App/H5、跨端或发布证明。 |

## High-value call-site reviews / 高价值调用点复核

- `USwitch` maps a real native boolean to the caller-configured `activeValue` or `inactiveValue`; do not retain a boolean-only assumption when either mapping is customized. / `USwitch` 会把真正的原生 boolean 映射到调用方配置的 `activeValue` 或 `inactiveValue`；任一映射被定制时，不要保留纯 boolean 假设。
- `UPicker.modelValue` is a selected scalar or complete selected-value array, not upstream popup visibility or region/time/column state. `USelect` and `UDropdown` own only inline/local state and do not acquire an upstream popup service. / `UPicker.modelValue` 是选中标量或完整选中值数组，不是上游 popup 可见性或地区/时间/列状态。`USelect` 与 `UDropdown` 只拥有 inline/local 状态，不取得上游 popup service。
- `UNumberBox` and `USlider` use distinct decimal-safe normalization rules, and `URate` remains integer-only with an explicit `current` presentation alias. Review bounds, steps, aliases, no-op behavior, and event order rather than preserving upstream numeric assumptions. / `UNumberBox` 与 `USlider` 使用不同的十进制安全规整规则，`URate` 仍只提供整数级别并具有显式 `current` 呈现 alias。应复核边界、step、alias、no-op 行为与事件顺序，而不是保留上游数值假设。
- `UUpload` keeps file state in the caller and only orchestrates an explicitly injected adapter. It has no built-in chooser, file-byte access, transport, URL/header/token construction, preview/delete implementation, or credential ownership. / `UUpload` 把文件状态保留在调用方，只编排显式注入的 adapter。它没有内建 chooser、文件字节访问、transport、URL/header/token 构造、preview/delete 实现或凭据所有权。
- `UButton`, `UIcon`, `UCellItem`, `UImage`, and `UText` do not share one click payload rule: review each linked contract. In particular, HIA returns original platform events where the fixed upstream may report no payload or an index. / `UButton`、`UIcon`、`UCellItem`、`UImage` 与 `UText` 并不共享一条 click payload 规则：必须分别复核关联契约。尤其是固定上游可能无载荷或报告 index，而 HIA 会在相应表面返回原始平台事件。
- `UPagination.change` reports a page number rather than the upstream change-detail object, and an accepted change is emitted in the fixed order `update:current` → `update:modelValue` → `change`. The component still performs no query. / `UPagination.change` 报告页码 number，而不是上游 change-detail 对象；合法变化按固定顺序 `update:current` → `update:modelValue` → `change` emit。组件仍不执行查询。
- `USwipeAction` is an explicit controlled action row, not a swipe engine. Replace row/action indexes with a safe string/number `value`, move callbacks into event handlers, and own `open`/`show` writeback in the application. / `USwipeAction` 是显式受控操作行，不是 swipe 引擎。应以安全 string/number `value` 替换 row/action index，把 callback 移入事件 handler，并由应用拥有 `open`/`show` 写回。
- `USkeleton.loading` should be bound explicitly, while `UEmpty` never infers empty/loading/query facts. `UTag` is informational by default and requires `clickable=true` for its body action; `UTag` and `UAlertTips` never hide themselves, and their close events are caller-owned intent. / `USkeleton.loading` 应显式绑定，而 `UEmpty` 绝不推断 empty/loading/query 事实。`UTag` 默认是信息标签，主体 action 需显式设置 `clickable=true`；`UTag` 与 `UAlertTips` 绝不自行隐藏，其 close 事件是调用方拥有的意图。

There is no codemod, source scanner, automatic import rewriter, or Tool `--write` mode for consumers. The repository's metadata generator `--write` option only refreshes the declared action JSON from reviewed matrix facts; it never opens or changes an application. Keep a migration diff reviewable, make one component boundary change at a time, and verify the application on its own supported environments. A future consumer-writing Tool feature needs separate authority, default dry-run behavior, safe-target allowlisting, overwrite refusal, and generated-code bilingual-comment checks.

不存在 codemod、源码扫描器、automatic import rewriter 或供 consumer 使用的 Tool `--write` 模式。仓库 metadata generator 的 `--write` 选项只从已审 matrix 事实刷新声明式 action JSON，绝不会打开或修改 application。应让迁移 diff 保持可审阅、一次只改变一个组件边界，并在应用自身支持的环境中验证。未来任何写 consumer 的 Tool 能力都需要独立授权、默认 dry-run、安全目标白名单、拒绝覆盖和生成代码双语注释检查。
