# HIA-uView-UI

This workspace contains the HIA-uView UniApp UI implementation and 107 pre-release component contracts, including navigation, safe-area, feedback, local-overlay, form, content, and layout surfaces. The complete set is maintained in the [component index](../docs/components.md), alongside HIA theme tokens, the component manifest, and compiler/build fixtures. It is not published and has no versioned external package API yet.

The initial target profile is UniApp Vue 3 on the WeChat Mini Program platform. H5 has bounded repository static-build smoke evidence but no runtime/support profile; App and other mini-program targets remain unvalidated, and none is promised yet. See the repository [compatibility profile](../docs/compatibility.md) and [HIA light-theme contract](../docs/theme.md).

The pre-release [component index](../docs/components.md) records the complete current set, including [UNavbar](../docs/navbar.md), [UNoticeBar](../docs/notice-bar.md), [UConfigProvider](../docs/config-provider.md), and the other navigation, feedback, and composition surfaces. `u-navbar` and `u-notice-bar` are distinct contracts, not aliases of the earlier `u-nav-bar` and `u-notice` APIs. Component contracts, accessibility expectations, styling tokens, and upstream-reference boundaries are published before implementation changes. See the [design-system contract](../docs/design-system.md). This package must not own application data, business flows, backend integration, or industry fields.

The precise caller-controlled families now include [UCheckbox](../docs/checkbox.md), [UCheckboxGroup](../docs/checkbox-group.md), [URadio](../docs/radio.md), [URadioGroup](../docs/radio-group.md), [USwitch](../docs/switch.md), [UPicker](../docs/picker.md), [UCalendar](../docs/calendar.md), [USelect](../docs/select.md), [UDropdown](../docs/dropdown.md), [UDropdownItem](../docs/dropdown-item.md), [UNumberBox](../docs/number-box.md), [URate](../docs/rate.md), [USlider](../docs/slider.md), and [UUpload](../docs/upload.md). They cover transparent choice values, finite selection/date drafts, an instance-local dropdown registry, decimal-safe numeric intent, and optional caller-injected upload-adapter orchestration. Each remains application-state controlled and independently documented.

The private runtime entry provides named component imports and an explicit `UView` Vue plugin; neither import automatically registers components or injects global styles. The package also exposes caller-owned, explicitly scoped `createUFeedbackScope`/`useToast`/`useModal` entries from the root and the pure `./services` subpath; they require opted-in `UToast`/`UModal` hosts and never discover a global page or service. The package has a bounded TypeScript entry, optional limited template augmentation, and a static `mp-weixin` Easycom fragment for a local package trial. These are private pre-release delivery surfaces, not publication or complete upstream-type compatibility guarantees. See [explicit feedback services](../docs/feedback-services.md), [private runtime consumption](../docs/runtime-consumption.md), and [private package consumption](../docs/private-package-consumption.md).

The [local catalog composition example](../docs/local-composition.md) combines the current components with application-owned anonymous mock data and local state. It is compiler/runtime evidence only, not a HIA-uView-Biz module, industry starter, backend contract, router, or device-support claim. Existing uView-family consumers should review the constrained [manual migration guidance](../docs/migration-from-uview.md) and the versioned [API compatibility inventory](../docs/api-compatibility.md); names are intentionally familiar, but no complete upstream compatibility or automatic migration is promised.
